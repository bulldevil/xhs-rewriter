# 终检流程（phase2-check）

触发：用户把人工修改过的六列 CSV 发回（"我改好了"/"检查这批"/直接附文件）。
定位产品：从 CSV 文件名或 `output/batches.md` 找到对应批次与产品，加载产品卡。若与 `state/current.md` 不一致，提示一句即可，以批次溯源为准。

核心原则：**人工修改优先**。用户已经改过的稿子，只修真正存在的问题，绝不为了"更高级"而大改。

## 一、检查清单

### 标题（每行的 标题1 / 标题2）

1. **字数**：≤20 字（最终数字以 `count_chars.py` 为准）
2. 错别字、语病、搭配错误、标点错误、重复用词
3. 表达不自然、逻辑不通、产品名称错误（对照产品卡）
4. 小红书感：口语自然、有点击欲、有情绪、有画面感、核心信息明确
5. Emoji：是否该加/该减（服务情绪与阅读节奏；已合适就保持）
6. **仿写度检查**：与该行的「对标标题」对照——句式骨架、核心钩子、情绪方向、产品关键词应仍在，防止人工改过头或此前仿写飘太远

### 正文（每行的 正文1 / 正文2）

1. **产品信息核对**：名称/材质/功能/参数/数量/价格/场景/卖点，逐条对照产品卡；卡片没有的信息（虚构卖点、虚构体验）必须删
2. 错别字、病句、重复表达、逻辑错误、前后矛盾、明显夸张
3. 小红书表达：开头有吸引力、句子自然、适合手机阅读、信息块清晰、情绪自然、Emoji 合适
4. 明显 AI 腔（对照 `shared-xhs-style.md` 第六节，改写为真人感）
5. SEO 关键词是否还在（产品卡非空时）
6. 固定Tag块是否还在收尾、是否原样
7. 格式：真实换行、无 HTML/Markdown 残留

## 二、修改原则

- 以用户原稿为基础做**小幅**修正；用户的人工修改一律优先保留
- 保持原有结构、表达风格、核心卖点、情绪、篇幅
- 只处理：明显错误、超 20 字、不自然表达、明显重复、Emoji 问题、虚构/越界信息、明显影响点击的表达

## 三、产出流程

1. 逐行检查并修正，修正结果写新的 JSON（沿用批次号，后缀 `-final`）：`output/_tmp/<批次号>-final.json`
2. 构建终版：`output/<slug>_<YYYYMMDD>_批NN_final.csv`
   （列结构不变，仍是六列——下游工具无感切换）
3. 复跑三项校验（count_chars / check_versions / validate_csv check），不过则修到过
4. `output/batches.md` 追加一条终检记录（原批次备注列联动）

⚠️ 对标标题/对标正文两列**仍然逐字不动**——人工也不该改，若发现被改，恢复原样并在汇报中说明。

## 四、汇报格式

总起一行（批次、产品、终版文件路径），然后每行一条修改说明（保持简短，多项用 `+` 连接）：

| 行 | 修改说明 |
|---|---|
| 1 | 无修改 |
| 2 | 压缩至20字+优化语序 |
| 3 | 删除虚构卖点（卡片中无此功效）+ 恢复固定Tag块 |

常用说明词：无修改 / 修正错别字 / 优化语序 / 优化表达 / 删除重复内容 / 压缩至20字 / 修正产品信息 / 删除虚构卖点 / 调整Emoji / 优化段落。
