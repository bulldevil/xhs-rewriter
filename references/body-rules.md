# 正文仿写规则（流水线子过程）

每条对标正文产出 **2 个版本**。上下文：当前产品卡 + 该条对标正文。通用方法论见 `shared-rewrite-rules.md`，素材见 `shared-xhs-style.md`。

## 一、骨架保留清单（仿写前逐项过一遍）

对标正文的以下要素，仿写后保持高度对应：

- 开头钩子（类型与位置）
- 段落结构、信息块数量、信息块顺序
- 痛点位置
- 产品卖点顺序与数量
- 使用场景
- 情绪节奏
- 收尾方式
- 标签结构（位置与密度）
- 整体篇幅

典型表达逻辑示例（保留其顺序）：

> 痛点 → 情绪 → 产品出现 → 卖点1 → 卖点2 → 使用场景 → 推荐

## 二、两个版本的定义

| 版本 | 策略 |
|---|---|
| 正文1「高还原」 | 最大程度保留原文句式和信息结构，只做必要的同义替换与产品信息替换 |
| 正文2「高还原+轻变化」 | 可调整：开头表达、部分句式、情绪词、Emoji、部分词语 |

两版遵循 `shared-rewrite-rules.md` 的共同差异标准；正文特有要求是信息块和卖点顺序不乱，差异要自然而不是机械替换。

## 三、产品信息（事实以产品卡为准）

以下信息严格按产品卡，卡片没有的不写：

- 产品名称、材质、功能、规格、数量、价格
- 核心卖点、使用场景、目标人群
- SEO 关键词（见下）

## 四、SEO 关键词融入

产品卡 `seo_keywords` 非空时：

- 自然融入正文，分布位置：开头 / 中段 / 收尾。
- 重复次数根据关键词数量和正文长度自然安排。
- 禁止为了密度破坏阅读感；禁止机械重复堆砌。

## 五、正文格式

1. **短句化**：一句一行，适合手机阅读。
2. **信息块分隔**：不同信息块之间可用 `·` 单独成行分隔，如：

```
每次打开行李箱都崩溃

·

这个收纳袋真的救了我
```

3. **Emoji**：按原文情绪自然使用，每个主要信息块约 1 个，服务情绪和阅读节奏。
4. **数字**：产品参数/数量/规格严格按产品卡，不擅自改；步骤类可用 `1⃣️ 2⃣️ 3⃣️`；价格、尺寸、时间用正常数字表达。

## 六、卖点规则

- 对标文案有几个核心卖点，仿写保持对应数量与顺序。
- 卖点可以换表达方式，产品事实保持一致。

## 七、标签规则（与产品卡联动）

- **固定 tag**：产品卡「固定Tag块」非空时，**原样整块挂在正文收尾**，两版都挂。这是产品的身份证，不改字、不改序。
- 对标文案自身的其他标签：与当前产品、内容相关的可保留其结构；无关的不留。
- 禁止自行大量增加与产品无关的标签。

## 八、格式处理（输出正文时）

- 使用真实换行，不用 `\n` 转义符、不用 HTML 标签
- 不输出 Markdown 链接
- 保留正常的小红书话题格式 `#话题`
- 删除从输入带入的格式代码残留

## 九、正文特有禁忌

- 不要为了 SEO 密度机械重复关键词。
- 不要为了制造两版差异虚构新的信息块或产品体验。
