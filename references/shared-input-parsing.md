# 共享规则：对标笔记解析（input-parsing）

把用户粘贴的内容解析成 N 条笔记，每条 = {对标标题, 对标正文}。解析结果是后续一切的地基。

## 一、输入单元与条数铁律

- 一条笔记 = 一个标题 + 一段正文。
- **N = 输出 CSV 的数据行数**。禁止合并、拆分、遗漏、新增笔记；禁止把多条对标融合成一条。

## 二、识别规则

用户粘贴形态多样，按以下优先级识别：

1. **推荐形态**：每条笔记第一行是标题，其余行是正文；多条之间用空行或 `---` 分隔。
2. **带前缀**：「标题：」「正文：」「Title:」等明确标记。
3. **带编号**：`1.` `①` `笔记1` 等分段标记。
4. **连续堆叠**：无明显分隔时，按语义边界（新出现钩子式短句 + 话题标签收尾）推断分段。

常见干扰的清理（只清格式，不动文字）：

- 删除 Markdown 语法残留、HTML 标签、超链接代码、多余空格和不可见字符。
- **保留**内容本身： emoji、`#话题`、换行结构、产品名称写法和标点。

## 三、置信度与何时反问

| 置信度 | 情形 | 动作 |
|---|---|---|
| 高 | 每条都能确定标题与正文的边界 | 直接进行，不打扰用户 |
| 中 | 某条缺标题（只有正文） | 问：这条是"全是正文"（标题留空待补）还是漏贴了标题？ |
| 低 | 条数无法确定 / 标题正文边界混乱 | 列出分段预览（每条的标题行），请用户确认后再继续 |

原则：不确定就问，不猜。解析错误会污染整条流水线和 CSV 锚点。

## 四、保真铁律（锚点不可动）

解析得到的「对标标题」「对标正文」将**原样**进入六列 CSV 的「对标标题」「对标正文」两列：

- 必须与用户输入**逐字一致**，一个标点、一个 emoji 都不改。
- 唯一允许的改动：清除上一条所述的格式代码。
- 不得润色、纠错、补全省略——原文是什么样，锚点就是什么样（行业违规词也原样保留，是否清洗是用户的事）。

## 五、解析产物（内部结构）

```
notes = [
  {"对标标题": "...", "对标正文": "..."},
  ...
]
```

进入流水线后，每条笔记 i 产出 CSV 的第 i 行，顺序与用户输入顺序严格一致。
